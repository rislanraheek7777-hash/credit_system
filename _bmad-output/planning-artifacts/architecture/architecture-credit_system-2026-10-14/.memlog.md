- (event) Architecture workspace initialized
- (constraint) Platform baseline: Flutter 3.47.5 stable, Dart 3.13.4, targeting Android and Web
- (constraint) Functional requirements: 33 verified requirements locked in approved PRD (prd.md)
- (direction) Working mode: Coaching Path
- (decision) AD-1 adopted: Drift (SQLite) local relational persistence with central cloud PostgreSQL and Row-Level Security (RLS)
- (constraint) Mandatory tenant_id on all tables with server-enforced RLS
- (constraint) Atomic ACID transactions for financial ledger balance updates
- (constraint) Append-only compensating entries for corrections; zero silent overwrites during offline sync
- (constraint) PendingServerAck vs ConfirmedByServer states for offline operation queue
- (decision) AD-2 adopted: Integer Minor Units with Immutable Money Value Object
- (constraint) 100 minor units per rupee (cents) for all LKR financial fields
- (constraint) Dedicated Money value object with strict operator overloading and currency equality validation
- (constraint) Strict prohibition of Dart double for monetary math and persistence
- (constraint) Database types: SQLite INTEGER and PostgreSQL BIGINT
- (constraint) FR-22 double-entry accounting formula enforced inside ACID transactions
- (constraint) Formatting strictly isolated to presentation layer
- (decision) AD-3 adopted: Riverpod State Management with Pure Dart Finite State Machines (FSM)
- (constraint) LoanFinancialState and CollateralCustodyState modeled as pure Dart independent state machines
- (constraint) OverallWorkflowStatus derived dynamically from financial + custody states
- (constraint) flutter_riverpod used for application controllers with AsyncValue
- (constraint) Granular 14-permission RBAC selectors on sessionProvider
- (constraint) Idempotency loading locks on UI action buttons
- (constraint) Loan-scoped payment lock when correction is pending approval
- (decision) AD-4 adopted: Feature-First Clean Architecture & Inward Dependency Rules
- (constraint) 9 feature modules: auth, shop, customers, collateral, loans, payments, overdue, reports, audit
- (constraint) core/ holds shared infrastructure: database, errors, money, permissions, sync, theme, utils
- (constraint) 3-layer internal separation per feature: domain, data, presentation
- (constraint) Inward dependency rule: domain has zero dependencies on Flutter, Drift, or HTTP
- (constraint) Structural source tree seed locked in ARCHITECTURE-SPINE.md
- (decision) AD-5 adopted: Client-Side Optimization, App-Private Local Storage & Private Object Storage with Signed URLs
- (constraint) Maximum 1600px dimension with 150-300KB target preserving gold hallmarks and serial numbers
- (constraint) Database stores metadata only (paths, hashes, sizes); zero image bytes in SQL tables
- (constraint) Platform-specific local storage: app documents sandbox on mobile/desktop, OPFS/IndexedDB on web
- (constraint) Private cloud object storage with time-bounded signed URLs (<= 15m) gated by RBAC
- (constraint) Retry-safe upload state machine with sha256 duplicate guards
- (constraint) Strict tenant-isolated storage pathing derived on server
- (decision) AD-6 adopted: Granular 14-Permission RBAC, Immediate Session Revocation & Database-Enforced Append-Only Audit Trails
- (constraint) Exact 14-permission catalog enforced with dual-layer checks (client Riverpod + server RLS/API)
- (constraint) Server session_version increment invalidates active counter sessions immediately on deactivation
- (constraint) Database trigger on audit_events strictly blocks UPDATE and DELETE statements
- (constraint) Mandatory business reasons required for corrections, exceptions, and due date extensions
- (constraint) Prohibited logging of credentials, tokens, or unnecessary sensitive identity data
- (constraint) Offline mode forbidden from bypassing authorization or approving corrections
- (decision) AD-7 adopted: Test Pyramid Strategy with Automated CI Pipeline & Risk-Prioritized Coverage
- (constraint) Base ~70% pure Dart domain unit tests: Money math, loan state machines, due-date calculation, ledger accounting formulas, 14 RBAC permissions
- (constraint) Middle ~20% integration tests: Drift SQLite migrations and rollbacks, real PostgreSQL RLS security verification, offline sync queues
- (constraint) Top ~10% counter flow widget tests: customer registration, loan creation, payment submission, receipt reprints
- (constraint) Mandatory CI quality gates (flutter analyze + flutter test) on all GitHub pull requests to main
- (constraint) Tests isolated from production data and credentials; verification limitations realistically documented
- (decision) AD-8 adopted: Provider-Neutral Disaster Recovery, Point-in-Time Recovery (PITR) & High Availability Architecture
- (constraint) Mandatory RPO <= 15 minutes and RTO <= 4 hours preserved; internal targets (<= 5m / <= 2h) subject to verified drill results
- (constraint) Database PITR via continuous WAL archiving, encryption at rest/transit, and secondary geo-redundancy
- (constraint) Zero silent overwrites or discarded records; post-restore ledger balance equality verification
- (constraint) Offline operation fault limits documented: unacknowledged local transactions at risk if counter device physically destroyed before sync
- (constraint) S3/R2 object versioning with tenant-partitioned object recovery
- (constraint) Mandatory pre-production disaster recovery drill clocking actual RPO/RTO
- (constraint) Provider-neutral capability evaluation gate before cloud deployment
- (event) All 8 core architecture decisions (AD-1 to AD-8) completed and adopted
